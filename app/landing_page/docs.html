POST /auth/signup

Register a New User

Creates a new user account and immediately sends an email verification link to the provided address.

Request Body (JSON)

{
  "email": "user@example.com",            // required
  "password": "MyP@ssword1",              // required — min 8 chars, must include uppercase,
                                          //   lowercase, number & special char (@$!%*?&)
  "redirectUrl": "https://yourapp.com/dashboard", // required
  "metadata": {                           // optional
    "name": "Aaqil khan",
    "phone": "+1234567890",
    "plan": "free"
  }
}

How to Use

Call this on your signup form submission.

email and password are required. Password must be at least 8 characters and include an uppercase letter, a lowercase letter, a number, and a special character (@$!%*?&).

redirectUrl is the page on YOUR app that the user lands on after clicking the verification link. Auth-Pro redirects there cleanly — no token is appended.

metadata accepts any JSON object. Store name, phone, role, plan, or anything else you need. These fields can be updated later with PATCH /users/me and are deep-merged on every update.

The response returns an accessToken (JWT) immediately — the user is logged in right away even before verifying their email.

Example Code (JavaScript / Fetch)

fetch('https://your-api-url.com/auth/signup', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email: 'user@example.com', password: 'MyP@ssword1', redirectUrl: 'https://yourapp.com/dashboard', metadata: { name: 'Aaqil khan', plan: 'free' } }) }) .then(res => res.json()) .then(data => { localStorage.setItem('token', data.accessToken); console.log('Signed up successfully!'); });
POST /auth/login

Login User

Authenticates an existing user with email and password and returns a JWT access token.

Request Body (JSON)

{
  "email": "user@example.com",  // required
  "password": "MyP@ssword1"     // required
}

// Response:
// { "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

How to Use

Call this when the user submits your login form.

On success you receive { "accessToken": "eyJ..." }. Store this token in localStorage or a secure cookie — you need it for every protected API call.

Attach it to protected requests via the header:
Authorization: Bearer <your-token>

The token is a standard JWT. You can decode it client-side to read the user's userId from the sub claim.

Returns 401 Unauthorized if the credentials are wrong or if the user has been banned.

Example Code (JavaScript / Fetch)

fetch('https://your-api-url.com/auth/login', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email: 'user@example.com', password: 'MyP@ssword1' }) }) .then(res => { if (!res.ok) throw new Error('Invalid credentials'); return res.json(); }) .then(data => { localStorage.setItem('token', data.accessToken); window.location.href = '/dashboard'; }) .catch(err => alert('Login failed: ' + err.message));
POST /auth/forgot-password

Forgot Password

Sends a secure, single-use password reset link to the user's email address.

Request Body (JSON)

{
  "email": "user@example.com",
  "redirectUrl": "https://yourapp.com/reset-password"
}

// Response (always the same regardless of whether email exists):
// { "message": "If the email exists, a reset link has been sent." }

How to Use

Call this when the user clicks "Forgot Password?" on your login page.

Auth-Pro generates a short-lived reset token and emails the user a link. That link redirects the user to YOUR redirectUrl with the token appended:
https://yourapp.com/reset-password?token=abc123xyz

Your reset page must then:
1. Read token from the URL
2. Show a "New Password" input
3. Call POST /auth/update-password with the token and new password

The response is always the same message — even if the email doesn't exist. This prevents email enumeration attacks.

Example Code (JavaScript / Fetch)

fetch('https://your-api-url.com/auth/forgot-password', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email: 'user@example.com', redirectUrl: 'https://yourapp.com/reset-password' }) }) .then(res => res.json()) .then(data => { alert('Check your inbox for a password reset link!'); });
POST /auth/update-password

Update / Reset Password

Sets a new password using the one-time reset token delivered via the forgot-password email.

Request Body (JSON)

{
  "token": "abc123xyz...",
  "newPassword": "NewP@ssword1"
}

// Response on success:
// { "message": "Password successfully updated." }

How to Use

Use this on your frontend reset-password page.

Step 1 — Extract the token on page load:
const token = new URLSearchParams(window.location.search).get('token');

Step 2 — Show a "New Password" input to the user.

Step 3 — On form submit, call this endpoint with the token and new password.

Reset tokens are single-use and time-limited — once used or expired, this endpoint returns 400. On success, redirect the user to the login page.

Example Code (JavaScript / Fetch)

const resetToken = new URLSearchParams(window.location.search).get('token'); document.querySelector('#resetForm').addEventListener('submit', async (e) => { e.preventDefault(); const newPassword = document.querySelector('#newPassword').value; const res = await fetch('https://your-api-url.com/auth/update-password', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ token: resetToken, newPassword }) }); const data = await res.json(); if (res.ok) { alert('Password updated! Please log in.'); window.location.href = '/login'; } else { alert('Error: ' + (data.message || 'Invalid or expired token.')); } });
GET /auth/verify-email

Verify Email Address

Confirms a user's email via the token sent at signup. This link is clicked directly from the email — you don't call it in code.

Query Parameters (no request body)

// This is a GET endpoint — no request body.
// The user clicks this link directly from their inbox.

// Query Parameters:
// token       (required) — the verification token
// redirectUrl (optional) — your frontend page to redirect to

// Example link in the email:
// https://your-api-url.com/auth/verify-email
//   ?token=TOKEN&redirectUrl=https://yourapp.com/dashboard

// If redirectUrl is provided  → redirects the user to that URL
// If redirectUrl is omitted   → returns JSON: { "message": "Email successfully verified." }
// If token is invalid/expired → returns 400

How to Use

You don't call this endpoint in your code. It is the destination of the email verification link that Auth-Pro automatically sends when a user signs up.

The full flow:
1. User signs up via POST /auth/signup — you pass a redirectUrl
2. Auth-Pro sends the user a verification email with a link pointing to this endpoint
3. User clicks the link — Auth-Pro marks their email as verified
4. Auth-Pro redirects the user to your redirectUrl

To control where the user lands after verification, set the redirectUrl correctly during signup.

Example Code (JavaScript / Fetch)

// You don't call this endpoint directly. // Just pass the correct redirectUrl during signup: fetch('https://your-api-url.com/auth/signup', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email: 'user@example.com', password: 'MyP@ssword1', // After the user clicks the verification email, they land here: redirectUrl: 'https://yourapp.com/dashboard', metadata: { name: 'Alice' } }) });
GET /auth/reset-password

Password Reset Redirect

Validates the reset link from the email and redirects the user to your frontend with the token appended to the URL.

Query Parameters (no request body)

// This is a GET redirect endpoint — no request body.
// The user clicks this link directly from their inbox.

// Query Parameters:
// token       (required) — the reset token
// redirectUrl (optional) — your frontend reset-password page

// What happens:
// Auth-Pro redirects the user to:
//   https://yourapp.com/reset-password?token=TOKEN
// Your page then reads that token and calls POST /auth/update-password

How to Use

You don't call this endpoint in your code. It is the link inside the forgot-password email.

When the user clicks it, Auth-Pro appends the token to your redirectUrl and redirects the browser:
https://yourapp.com/reset-password?token=abc123xyz

Your page then extracts the token from the URL and calls POST /auth/update-password.

Always set the redirectUrl in your forgot-password call.

Example Code (JavaScript / Fetch)

// You don't call this endpoint directly. // Set up the flow correctly in your forgot-password call: fetch('https://your-api-url.com/auth/forgot-password', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email: 'user@example.com', redirectUrl: 'https://yourapp.com/reset-password' }) }); // Then on your /reset-password page: const token = new URLSearchParams(window.location.search).get('token'); // Pass this token to POST /auth/update-password
GET /users/me 🔒 Auth Required

Get Current User Profile

Returns the full profile of the authenticated user including id, email, avatarUrl, metadata, and verification status.

Required Header (no request body)

// No request body.
// Required Header:
// Authorization: Bearer YOUR_JWT_TOKEN

// Response shape:
{
  "id": "clx9ab12cd34ef56",
  "email": "user@example.com",
  "avatarUrl": "https://cdn.example.com/avatars/abc.webp",
  "metadata": { "name": "Aaqil khan", "plan": "pro" },
  "isEmailVerified": true,
  "createdAt": "2025-01-01T00:00:00.000Z",
  "updatedAt": "2025-06-01T12:00:00.000Z"
  // "password" is NEVER returned
}

How to Use

Call this on any page that needs user data — your dashboard, settings page, profile page, etc.

The response includes:
• id — unique user ID (needed for admin operations like ban)
• email — the user's email address
• avatarUrl — cloud CDN URL of their profile picture (null if not set)
• metadata — any custom JSON you stored (null if nothing stored yet)
• isEmailVerified — whether the user has clicked their verification email link

The password field is never returned. Returns 401 if the token is missing, invalid, or expired.

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); fetch('https://your-api-url.com/users/me', { headers: { 'Authorization': `Bearer ${token}` } }) .then(res => { if (res.status === 401) throw new Error('Not authenticated'); return res.json(); }) .then(user => { console.log('Email:', user.email); console.log('Verified:', user.isEmailVerified); if (user.avatarUrl) { document.querySelector('#avatar').src = user.avatarUrl; } });
PATCH /users/me 🔒 Auth Required

Update User Metadata

Deep-merges custom metadata into the user's profile. Only keys you send are updated — all existing metadata is preserved.

Request Body (JSON)

{
  "metadata": {
    "displayName": "Alice",
    "theme": "dark",
    "onboardingStep": 3
  }
}

// IMPORTANT: This is a MERGE, not a replace.
// To delete a key, send it as null:
// { "metadata": { "oldKey": null } }

How to Use

Use this to save any custom user-level data — UI preferences, settings, onboarding state, plan details, etc.

Merge behaviour: The server deep-merges your payload into existing metadata. Keys not included in your payload are untouched.

Deleting a key: Send the key with a null value:
{ "metadata": { "keyToRemove": null } }

Returns the full updated user object on success. Returns 401 if unauthenticated.

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); fetch('https://your-api-url.com/users/me', { method: 'PATCH', headers: { 'Content-Type': 'application/json', 'Authorization': `Bearer ${token}` }, body: JSON.stringify({ metadata: { theme: 'dark', displayName: 'Alice', onboardingComplete: true } }) }) .then(res => res.json()) .then(user => console.log('Updated metadata:', user.metadata));
POST /users/avatar 🔒 Auth Required

Upload Profile Picture

Uploads a profile image for the authenticated user. Automatically compressed to WebP and stored in cloud storage.

Multipart Form Data

// Authorization: Bearer YOUR_JWT_TOKEN
// Content-Type: multipart/form-data ← set AUTOMATICALLY, do NOT set manually

// Form Fields:
// file — (required) the image file (JPG, PNG, WebP, etc.)

// Response: full UserEntity with updated avatarUrl field

How to Use

Use an HTML <input type="file" accept="image/*"> to let the user pick an image. Build a FormData object and append the file under the key "file".

Critical: Do NOT set Content-Type manually. The browser adds it automatically with the correct multipart boundary string.

The image is automatically compressed and converted to WebP format before being saved to cloud storage. Use user.avatarUrl as the src of an <img> tag to display the avatar.

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); const fileInput = document.querySelector('#avatarInput'); fileInput.addEventListener('change', async () => { const file = fileInput.files[0]; if (!file) return; const formData = new FormData(); formData.append('file', file); // field name MUST be "file" const res = await fetch('https://your-api-url.com/users/avatar', { method: 'POST', headers: { 'Authorization': `Bearer ${token}` // DO NOT add Content-Type here! }, body: formData }); const user = await res.json(); document.querySelector('#avatarImg').src = user.avatarUrl; });
POST /users/ban 🛡 Admin Only

Ban User (Admin)

Permanently bans a user account by their ID. Requires the server-side admin password. No JWT needed.

Request Body (JSON)

{
  "adminPass": "your-admin-password",
  "userId": "clx9ab12cd34ef56gh78"
}

// Returns 401 if adminPass is wrong
// Returns 404 if userId does not exist

How to Use

Admin-only endpoint — no JWT required. Authentication is done via the adminPass field, which must match the ADMIN_PASS environment variable on the server.

To get a user's userId, call GET /users/me while authenticated as that user, or look it up in your database.

Security: Never expose this endpoint or adminPass in a public frontend. Only call it from a secure server-side admin panel or CLI tool.

Example Code (JavaScript / Fetch)

// Admin-only — run from a secure server-side context! fetch('https://your-api-url.com/users/ban', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ adminPass: 'your-admin-password', userId: 'clx9ab12cd34ef56gh78' }) }) .then(res => res.json()) .then(data => { if (data.statusCode === 401) console.error('Wrong admin password!'); else if (data.statusCode === 404) console.error('User not found!'); else console.log('User banned:', data.id); });
POST /mail/send-custom 🛡 Admin Only

Send Custom Email (Admin)

Sends a fully custom HTML email to any address on behalf of your application. Requires the admin password.

Request Body (JSON)

{
  "adminPass": "your-admin-password",
  "to": "recipient@example.com",
  "subject": "Welcome to Our Platform!",
  "htmlTemplate": "<h1>Hello!</h1><p>...</p>"
}

// Response on success:
// { "message": "Email successfully sent." }

How to Use

Admin-only endpoint — no JWT required.

The htmlTemplate field accepts complete HTML. Tips for best email client compatibility:
• Use inline CSS (style="..." attributes) — most email clients strip external <style> tags
• Use table-based layouts for complex designs
• Keep image src URLs absolute

Returns 401 if the admin password is wrong.

Example Code (JavaScript / Fetch)

fetch('https://your-api-url.com/mail/send-custom', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ adminPass: 'your-admin-password', to: 'newuser@example.com', subject: 'Welcome to Our Platform!', htmlTemplate: ` <div style="font-family:Arial,sans-serif;max-width:600px;padding:24px"> <h1 style="color:#3b82f6">Welcome aboard!</h1> <p>Your account is ready.</p> <a href="https://yourapp.com/dashboard" style="display:inline-block;background:#3b82f6;color:#fff; padding:12px 24px;text-decoration:none;border-radius:6px"> Go to Dashboard </a> </div> ` }) }) .then(res => res.json()) .then(data => console.log(data.message));
POST /media/images 🔒 Auth Required

Upload Image to Media Library

Uploads and compresses an image into the user's personal media library with a required tag for categorization.

Multipart Form Data

// Authorization: Bearer YOUR_JWT_TOKEN
// Content-Type: set automatically by FormData

// Form Fields:
// file — (required) the image file
// tag  — (required) category label e.g. "blog-thumbnails"

// Response (MediaEntity):
{
  "id": "clx9ab12cd34ef56",
  "url": "https://cdn.example.com/media/images/uuid.webp",
  "tag": "blog-thumbnails",
  "mimeType": "image/webp",
  "size": 45312,
  "filename": "media/images/uuid.webp",
  "createdAt": "2025-06-01T00:00:00.000Z"
}

How to Use

This is different from POST /users/avatar — that sets one profile picture. This builds a full media library with multiple organized files per user.

The tag field is required and is how you group and retrieve images later:
• "blog-thumbnails" for article cover images
• "project-alpha" for project-specific assets

The image is compressed to WebP automatically. Save the response id if you need to delete the file later.

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); async function uploadToMediaLibrary(file, tag) { const formData = new FormData(); formData.append('file', file); formData.append('tag', tag); const res = await fetch('https://your-api-url.com/media/images', { method: 'POST', headers: { 'Authorization': `Bearer ${token}` }, body: formData }); const media = await res.json(); console.log('URL:', media.url); console.log('ID:', media.id); // save to delete later return media; }
GET /media 🔒 Auth Required

List User Media

Returns all media files uploaded by the authenticated user. Optionally filter by tag.

Query Parameters (no request body)

// Authorization: Bearer YOUR_JWT_TOKEN

// Optional Query Parameter:
// ?tag=your-tag  — filter results to only files with this tag

// GET /media                     → all media files
// GET /media?tag=blog-thumbnails → only files tagged "blog-thumbnails"

// Returns [] (empty array) if no files found — not 404

How to Use

Use the optional ?tag= query parameter to filter results by category. Each item includes:
• id — use to fetch or delete a specific file
• url — public CDN URL to display in an <img> tag
• tag — the category label
• size — file size in bytes after compression
• createdAt — upload timestamp

Returns an empty array [] if no files exist — not a 404.

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); async function getMediaByTag(tag) { const url = `https://your-api-url.com/media?tag=${encodeURIComponent(tag)}`; const res = await fetch(url, { headers: { 'Authorization': `Bearer ${token}` } }); return res.json(); } getMediaByTag('blog-thumbnails').then(images => { const gallery = document.querySelector('#gallery'); images.forEach(img => { const el = document.createElement('img'); el.src = img.url; el.dataset.mediaId = img.id; gallery.appendChild(el); }); });
GET /media/:id 🔒 Auth Required

Get Single Media File

Returns the full details of a specific media file by its unique ID.

Path Parameter (no request body)

// Authorization: Bearer YOUR_JWT_TOKEN
// :id — the unique media file ID

// Example: GET /media/clx9ab12cd34ef56gh78

// Response (MediaEntity):
{
  "id": "clx9ab12cd34ef56gh78",
  "url": "https://cdn.example.com/media/images/uuid.webp",
  "tag": "blog-thumbnails",
  "mimeType": "image/webp",
  "size": 45312,
  "createdAt": "2025-06-01T00:00:00.000Z"
}

How to Use

Use this to retrieve the complete details of a single uploaded file by its id.

The id is returned when you upload an image and is included in every item from GET /media.

Access control: Only returns files owned by the currently authenticated user. If the ID belongs to another user's file, the server returns 404 (not 403 — to prevent ID enumeration).

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); const mediaId = 'clx9ab12cd34ef56gh78'; fetch(`https://your-api-url.com/media/${mediaId}`, { headers: { 'Authorization': `Bearer ${token}` } }) .then(res => { if (res.status === 404) throw new Error('File not found or access denied'); return res.json(); }) .then(media => { console.log('URL:', media.url); document.querySelector('#previewImg').src = media.url; });
DELETE /media/:id 🔒 Auth Required

Delete Media File

Permanently deletes a media file from both the database and cloud storage. This action cannot be undone.

Path Parameter (no request body)

// Authorization: Bearer YOUR_JWT_TOKEN
// :id — the unique media file ID to delete

// Example: DELETE /media/clx9ab12cd34ef56gh78

// Response on success:
// { "message": "Media successfully deleted" }

// After deletion:
// - The file's URL will return 404 from cloud storage
// - PERMANENT — cannot be undone

How to Use

Permanently deletes the media file — both the database record and the file in cloud storage. This is irreversible.

Only the owner of the file can delete it. Attempting to delete another user's file returns 404.

Best practice: Always confirm with the user before calling delete. Returns 401 if unauthenticated.

Example Code (JavaScript / Fetch)

const token = localStorage.getItem('token'); async function deleteMedia(mediaId) { const confirmed = confirm('Delete this file? This cannot be undone.'); if (!confirmed) return; const res = await fetch(`https://your-api-url.com/media/${mediaId}`, { method: 'DELETE', headers: { 'Authorization': `Bearer ${token}` } }); const data = await res.json(); if (res.ok) { console.log(data.message); document.querySelector(`[data-media-id="${mediaId}"]`)?.remove(); } else { console.error('Delete failed:', data); } } document.querySelectorAll('.delete-media-btn').forEach(btn => { btn.addEventListener('click', () => deleteMedia(btn.dataset.mediaId)); });
