What Auth-Pro Actually Does

Almost every app needs the same three things: a way for users to sign up and log in, a way to email them, and a way to store their files. Auth-Pro is a small, self-hosted server that does all three: you deploy it once, plug in your own credentials, and get a working REST API back.

🔐

Authentication

JWT-based signup, login, email verification, and password reset: all using your own PostgreSQL database. Your data, your server, your rules.

📧

Email Delivery

Plug in any SMTP provider: Resend, SendGrid, Gmail SMTP, or your own mail server. Full control over every email template sent to your users.

🗄️

Media Storage

Avatars and image libraries stored in your own Cloudflare R2 bucket. Auto-compressed to WebP, tagged per user, served from your CDN.

Option 1

Build Your Project on Auth-Pro

Clone the repo and use it as the foundation of your own backend. Auth, email, and storage are already solved: you just add your own API routes, database tables, and business logic on top.

Best for: starting a brand-new app or SaaS from scratch.

Step 1 · Both Paths

Get Your Environment Keys

Whichever path you chose, you'll need these. Copy .env.example to .env in your cloned project, then work through each card below. Click Show Steps for exactly where to get each value: nothing here requires prior DevOps experience.

💡 Tip: once your app is running (locally or deployed), it also ships with a built-in Setup Dashboard at its root URL that shows you, live, which of these keys are still missing, so you can't get this step wrong for long.

🗄️ Database · required

DATABASE_URL Required

The pooled Postgres connection string Prisma uses for normal queries.

  1. Create a free project at neon.tech (or use any Postgres provider).
  2. Open your project dashboard → Connection Details.
  3. Copy the Pooled connection string.
Add this to your .env
DATABASE_URL="postgresql://user:password@hostname/dbname?pgbouncer=true&connect_timeout=15"
DIRECT_URL Required

The direct (non-pooled) connection string Prisma uses for migrations.

  1. On the same Neon dashboard, switch to the Direct connection string.
  2. Paste it as DIRECT_URL.
  3. Once both URLs are set, run npx prisma generate && npx prisma db push to create the tables.
Add this to your .env
DIRECT_URL="postgresql://user:password@hostname/dbname?connect_timeout=15"

🔐 Authentication (JWT) · required

JWT_SECRET Required

Signs and verifies session tokens. Must be a long random string.

  1. Run openssl rand -base64 32 in your terminal (or use any long random string).
  2. Copy the output and paste it as JWT_SECRET.
Add this to your .env
JWT_SECRET="your-super-secret-jwt-key"
JWT_EXPIRES_IN Optional · default 1d

How long issued tokens remain valid, e.g. 1h, 12h, 7d.

Leave unset for a sensible 1-day default, or set your own duration string.

Add this to your .env
JWT_EXPIRES_IN="1d"

☁️ File Storage (Cloudflare R2) · optional, powers avatars & media

R2_ACCOUNT_ID · R2_ACCESS_KEY_ID · R2_SECRET_ACCESS_KEY · R2_BUCKET_NAME · R2_PUBLIC_URL Optional

Five keys, one dashboard. Without these, avatar/media upload endpoints fail: the rest of the app works fine.

  1. Sign up at dash.cloudflare.com and open the R2 section.
  2. Create a bucket, its name is your R2_BUCKET_NAME.
  3. Copy your Account ID from the R2 overview page → R2_ACCOUNT_ID.
  4. Go to Manage R2 API Tokens → create a token with read/write access → copy the Access Key ID and Secret Access Key (shown once).
  5. Enable public access (or attach a custom domain) on the bucket → copy the public URL → R2_PUBLIC_URL.
Add these to your .env
R2_ACCOUNT_ID="your-cloudflare-account-id"
R2_ACCESS_KEY_ID="your-r2-access-key-id"
R2_SECRET_ACCESS_KEY="your-r2-secret-access-key"
R2_BUCKET_NAME="your-r2-bucket-name"
R2_PUBLIC_URL="https://your-r2-public-url.com"

📧 Email (SMTP) · optional, powers verification & reset emails

SMTP_HOST · SMTP_PORT · SMTP_USER · SMTP_PASS · SMTP_FROM Optional

Without these, signup/login still work: only verification and password-reset emails fail to send.

  1. Pick a transactional email provider: Resend, SendGrid, AWS SES, or even Gmail (with an App Password) for testing.
  2. Copy the SMTP host and port they give you (587 for STARTTLS, 465 for SSL).
  3. Copy your SMTP username and password/API key.
  4. Set a verified sender address for SMTP_FROM.
Add these to your .env
SMTP_HOST="smtp.example.com"
SMTP_PORT="587"
SMTP_USER="your-smtp-username"
SMTP_PASS="your-smtp-password"
SMTP_FROM='"Auth-Pro" <noreply@example.com>'

🛡️ Admin Access · optional

ADMIN_PASS Optional

Guards admin-only endpoints (ban user, send custom mail): no external service needed.

Pick any strong password/string of your own choosing and set it below. Use that exact value in the adminPass field when calling admin-only endpoints. Never expose it in a public frontend.

Add this to your .env
ADMIN_PASS="your-custom-password"

⚙️ Application Settings · optional, safe defaults

PORT · PRODUCTION · API_URL · FRONTEND_URL Optional

All four have safe defaults locally: PORT=3000, PRODUCTION=false, API_URL=http://localhost:3000. You'll update API_URL and PRODUCTION once you deploy.

  • PORT: which port the server listens on. Leave unset unless your host requires a specific one.
  • PRODUCTION: set to true in a real deployment (disables the Swagger UI, tightens security). Leave false locally.
  • API_URL: the public base URL of your API, used to build links in emails. Set this to your deployed URL once you have one.
  • FRONTEND_URL: optional fallback if your frontend lives on a different domain than the API.
Add these to your .env
PORT=3000
PRODUCTION=false
API_URL=http://localhost:3000
Step 2 · Both Paths

Clone, Install & Run It Locally

Do this before deploying anywhere: it's the fastest way to confirm everything is wired up correctly.

1

Clone the repository

git clone https://github.com/ABDULAAQILKHAN/AUTH-PRO.git
cd AUTH-PRO
2

Install dependencies

npm install

Uses sharp for image compression: install its system dependencies first if you hit build errors.

3

Add your environment keys

cp .env.example .env

Fill in the values from Step 1 above.

4

Start the app

npx prisma generate && npx prisma db push
npm run start:dev

Auth-Pro boots even with an incomplete .env. Open http://localhost:3000, you'll land on the built-in Setup Dashboard, which shows the live status of every key from Step 1 and re-checks itself every time you restart the server.

Step 3 · Both Paths

Deploy It & Get a Public URL

Auth-Pro ships with a Dockerfile, so any container host works. Here's the walkthrough using Northflank as a concrete, beginner-friendly example.

1

Push your clone to your own GitHub repository

Northflank deploys from a Git repo, so make sure your clone (with your changes, if any) is pushed there.

2

Create a Northflank account & project

Sign up at northflank.com (a free tier is available) and create a new Project.

3

Create a new Service from your repo

Choose Create new service → Deployment → Import from Git repository, connect GitHub, and select your Auth-Pro repo and branch. Northflank auto-detects the Dockerfile at the repo root, so no extra build config is needed.

4

Add your environment variables

In the service's Environment variables tab, add every key from your local .env, the exact same set from Step 1.

5

Expose the port

Under Networking, add a public HTTP port pointing at 3000 (matching PORT and the Dockerfile's EXPOSE 3000) so Northflank issues you a public URL.

6

Deploy

Click Deploy. Northflank builds your Docker image and starts the container: this takes a couple of minutes the first time.

7

Copy your generated URL

Once live, Northflank gives you a public URL like https://p01--auth-pro--xxxxxxxxxxxx.code.run.

8

Point Auth-Pro at its own URL

Go back into the environment variables, set API_URL to that exact URL and PRODUCTION=true, then redeploy. Visit the URL, you'll see the live Setup Dashboard and /docs confirming everything is wired up.

Step 4 · This Is Where You Split

Now Follow Your Path

🚀 Option 1

Building Your Own Project

You already have Auth-Pro cloned and deployed. Now make it yours:

  1. 1.Add your own tables: open prisma/schema.prisma, add new models below the existing User/Media models, then run npx prisma generate && npx prisma db push.
  2. 2.Add your own API routes: create a new folder under src/ (e.g. src/posts/) following the same module/controller/service pattern as src/users/, then register it in src/app.module.ts.
  3. 3.Protect your new routes: reuse the existing JWT guard with @UseGuards(AuthGuard('jwt')), and read the logged-in user from req.user exactly like UsersController does.
  4. 4.Reuse the metadata field for anything custom: the existing metadata JSON field on User can store arbitrary per-user data via PATCH /users/me before you need a dedicated table.
  5. 5.Redeploy: push to GitHub. Northflank can auto-redeploy on every push, or trigger one manually from its dashboard.

Your new endpoints now live at the same base URL as Auth-Pro's built-in ones, one deployed service, one URL, your whole backend.

🔌 Option 2

Using It As a Standalone Service

You already have Auth-Pro deployed on its own URL. Now call it from your app:

  1. 1.Open /docs on your deployed URL: the interactive API reference with ready-to-paste JavaScript for every endpoint.
  2. 2.Click "Copy AI Prompt" on that page and paste it into Claude, ChatGPT, or any AI along with a description of your app. It has everything needed to generate your whole frontend integration in one go.
  3. 3.CORS is already enabled: main.ts calls app.enableCors(), so your separate frontend (any framework, any domain) can call this URL directly from the browser, no extra config.
  4. 4.Treat it like Supabase or Firebase Auth: sign up/login from your app, store the returned accessToken, and attach it as Authorization: Bearer <token> on every protected request.

Your main project's codebase never needs to know Auth-Pro exists beyond a base URL and a bearer token.
